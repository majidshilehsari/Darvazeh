# پنل پیشرفته — 0.2.0-preview.1

## چه چیزی واقعی و چه چیزی محدود است؟

- مدیریت حداکثر ۵۰ دستگاه نام‌گذاری‌شده؛ UUID مستقل، دریافت لینک، فعال/غیرفعال، تغییر نام و تعویض کلید. نام دستگاه را مدیر می‌نویسد؛ تشخیص برند، مدل، MAC یا مالک فیزیکی انجام نمی‌شود. دارندهٔ لینک می‌تواند آن را به دیگری بدهد.
- اتصال قبلی با شناسهٔ `legacy` و **همان UUID** باقی می‌ماند. افزودن کاربر، UUID قبلی را عوض نمی‌کند. دکمهٔ تعویض کلید فقط با تأیید صریح، کلید دستگاه انتخاب‌شده را تغییر می‌دهد.
- شروع و پایان اتصال WS، آخرین مشاهده، مدت مشاهده‌شده و حجم بایت عبوری هر دو جهت ثبت می‌شود. یک دستگاه می‌تواند چند اتصال هم‌زمان داشته باشد؛ عدد اتصال باز تعداد افراد نیست.
- انتساب دستگاه بر اساس مشاهدهٔ نسخه و UUID در ۱۷ بایت آغاز VLESS پس از handshake WebSocket است. این مشاهده به‌تنهایی اثبات موفقیت درخواست به مقصد یا اعتبار بقیهٔ پیام VLESS نیست. هسته همچنان احراز اتصال و درخواست را انجام می‌دهد. مقصد/محتوا ثبت نمی‌شود.
- شمارنده‌ها مربوط به **wire bytes بعد از HTTP upgrade با سربار WebSocket** هستند، نه حجم صورتحساب اینترنت و نه شمارندهٔ خالص Xray. هر ۱۵ ثانیه و هنگام بسته‌شدن ذخیره می‌شوند. در crash ممکن است آخرین بازه از دست برود.
- اگر پنل غیرمنتظره قطع شود، اتصال قبلی «پایان نامشخص» و زمان آخرین مشاهده ثبت‌شده را نشان می‌دهد؛ مدت قطعی یا ساعت خاموش‌شدن دستگاه جعل نمی‌شود.
- حالت نمایشی هیچ نشست یا مصرف ساختگی نمی‌سازد. خاموش‌بودن پایش هم باید در پنل دیده شود.
- پروفایل فعلی WS قابل دریافت است. پروفایل تنظیم کلاینت راهنمای دستی است. XHTTP فقط گزینهٔ پژوهشی/دفتر تست است و ورودی یا لینک XHTTP جدیدی ایجاد نشده است.

## مسیر اجرا

```text
Hostim HTTPS → Nginx:8080
  /              → Python panel:8081
  /connect       → observer:10001 → Xray:10000
```

همهٔ پورت‌های داخلی روی loopback هستند. مشاهده‌گر websocket یک واسط انتقال شفاف است و رشتهٔ مقصد درخواست را در DB یا لاگ ذخیره نمی‌کند. حداکثر ۲۵۶ اتصال هم‌زمان، header تا 16KiB، idle timeout یک ساعت، سقف مشاهدهٔ اتصال حدود ۲۴ ساعت در نظر گرفته شده است؛ این اعداد سقف حفاظتی‌اند نه ادعای ظرفیت بنچمارک‌شده.

**Early Data:** اگر `Sec-WebSocket-Protocol` حامل دادهٔ اولیه باشد، ترافیک منتقل می‌شود ولی این نسخه آن را به دستگاه منتسب و ثبت نمی‌کند. لینک‌های صادرشده Early Data ندارند. شمارندهٔ ناقص را با مصرف کل واقعی یکی نگیرید.

## IP واقعی پشت Hostim

Nginx خودش `X-Darvazeh-Peer` را با peer واقعی ورودی و `X-Darvazeh-Forwarded` را با XFF دریافت‌شده بازنویسی می‌کند. مشاهده‌گر بدون پیکربندی صریح به XFF اعتماد نمی‌کند؛ هدرهای اصلی XFF را پیش از ارسال به Xray حذف می‌کند تا هسته هم به IP جعلی اعتماد نکند.

متغیر اختیاری:

```text
TRUSTED_PROXY_CIDRS=<فقط CIDRهای رسمی و تأییدشدهٔ reverse proxy میزبان>
```

این مقدار را **خالی نگه دارید تا میزبان آن را تأیید کند**. IP عمومی `91.98.208.35` یا کل شبکهٔ خصوصی را بدون مدرک به این فهرست تبدیل نکنید. `0.0.0.0/0` و `::/0` به معنی اعتماد به همه‌اند و نباید استفاده شوند.

زنجیرهٔ XFF از راست به چپ فقط تا زمانی پیمایش می‌شود که واسط فعلی مورد اعتماد باشد. IP نهایی خصوصی/نامعتبر یا نبود زنجیره باعث «نامشخص» می‌شود. در حالت پیش‌فرض peer مشاهده‌شده با برچسب **واسط** نمایش داده می‌شود، نه IP کاربر.

متن پیشنهادی برای پشتیبانی Hostim:

> Which source CIDRs can reach my application's HTTP port from your ingress? Do you overwrite or safely append X-Forwarded-For and strip spoofed forwarding headers? What is the supported trusted-proxy configuration for recovering the original client IP?

بدون پاسخ معتبر، نمایش کشور/اپراتور واقعی کاربران تضمین‌شدنی نیست.

## کشور بدون ارسال IP به سرویس خارجی

در Docker کتابخانهٔ `python3-maxminddb` نصب می‌شود. فایل پایگاه کشور سازگار MMDB را با رعایت مجوز تأمین‌کننده، خصوصی روی Volume در مسیر زیر قرار دهید:

```text
/data/GeoLite2-Country.mmdb
```

دادهٔ جغرافیایی داخل Git یا ایمیج قرار داده نشده است. برنامه IP را برای lookup به API خارجی نمی‌فرستد. پس از قراردادن/به‌روزرسانی فایل، Restart لازم است. بانک برای اتصال‌های جدید استفاده می‌شود؛ سوابق گذشته خودکار بازنویسی نمی‌شوند. در نبود فایل یا IP مورداعتماد، کشور «نامشخص» باقی می‌ماند. IP موقعیت خروج شبکه را نشان می‌دهد، نه GPS یا محل قطعی کاربر.

## داده، حریم خصوصی و نگهداری

- فایل جدید: `/data/history.sqlite3`، schema version 1، WAL، مجوز خصوصی. DB مکمل است؛ منبع معتبر دستگاه‌ها همچنان `settings.json` است.
- پیش از نخستین اعمال این نسخه، کپی افزایشی تنظیمات موجود در `/data/backups/settings-before-0.2.0.json` ذخیره می‌شود؛ اگر وجود دارد بازنویسی نمی‌شود. حاوی کلید اتصال است و نباید عمومی شود.
- فایل دادهٔ خراب/نسخهٔ ناشناخته خودکار بازسازی نمی‌شود. خطای تاریخچه در پنل نمایش داده می‌شود. در صورت خرابی DB، relay تا حد امکان ترافیک را عبور می‌دهد و نبود ثبت آمار را هشدار می‌دهد؛ بدون جعل آمار.
- حداکثر ۷ روز از آخرین مشاهده برای تاریخچهٔ بسته‌شده و نتیجهٔ آزمایش؛ همچنین سقف ۵۰٬۰۰۰ اتصال بسته و ۱۰۰۰ نتیجهٔ تست وجود دارد. پاک‌سازی تقریباً هر ۳۰ ثانیه و هنگام خواندن تاریخچه انجام می‌شود. این حذف منطقی در SQLite است، نه پاک‌سازی forensic فضای دیسک.
- snapshot تاریخچهٔ پیش از مهاجرت (در صورت وجود) نیز پس از ۷ روز حذف می‌شود. بکاپ تنظیمات چون تاریخچهٔ IP ندارد مشمول این پاک‌سازی نیست. بکاپ‌های بیرونی میزبان تحت کنترل این برنامه نیستند.
- خروجی عمومی `/api/bootstrap` دادهٔ کاربران ندارد؛ APIهای دستگاه/تاریخچه/پروفایل نیازمند نشست مدیر هستند؛ عملیات نوشتن CSRF می‌خواهد.
- گزارش عمومی عیب‌یابی همان خروجی پاک‌سازی‌شده است و IPها/نام دستگاه/UUID را شامل نمی‌شود. **دانلود تاریخچهٔ خصوصی** جداست، تأیید می‌خواهد و شامل IP و زمان اتصال است؛ برای انتشار عمومی مناسب نیست.
- قبل از ثبت اطلاعات کاربران، سیاست ثبت IP و زمان را به آن‌ها اعلام کنید. مقصد سایت، محتوای ترافیک، رمز و UUID در جدول تاریخچه ذخیره نمی‌شوند.
- نمایش تاریخ شمسی و ساعت تهران در UI؛ ذخیرهٔ timestamps به‌صورت epoch است.

## ارتقای امن و بازگشت

1. توصیه: ابتدا روی اپ آزمایشی با Volume مستقل امتحان کنید. تنها replica مجاز برای این طراحی **۱** است. دو پنل را به یک settings/SQLite مشترک متصل نکنید.
2. برای ارتقای اپ موجود، از قابلیت بکاپ/اسنپ‌شات میزبان نسخهٔ امن از Volume بگیرید؛ اپ یا Volume را حذف نکنید. تنظیمات قبلی همچنان معتبرند.
3. شاخهٔ `arena/01a080a2-darvazeh` را Rebuild کنید. نسخهٔ صفحه باید `0.2.0-preview.1` باشد.
4. `MONITOR_ENABLED` به‌صورت پیش‌فرض `1` است؛ دستگاه جدید بسازید و لینک اختصاصی را فقط روی همان دستگاه امتحان کنید. تغییر دستگاه فعلاً هسته را restart و اتصال‌های جاری را قطع می‌کند.
5. اگر واسط پایش مشکل اتصال ایجاد کرد، این مقدار را در Envs ذخیره و **Restart** کنید:

```text
MONITOR_ENABLED=0
```

entrypoint سپس Nginx را به مسیر مستقیم قدیمی `10000` برمی‌گرداند؛ لینک‌ها، UUIDها و DB حذف نمی‌شوند. در این حالت دادهٔ اتصال جدید جمع نمی‌شود و پنل صریحاً پایش خاموش را نشان می‌دهد.

6. برای بازگشت کامل ایمیج، نسخهٔ قبلی `aa60cb6` را از امکانات استقرار میزبان انتخاب کنید (main را تغییر ندهید). نسخهٔ قدیمی فقط UUID اصلی را می‌شناسد؛ لینک‌های دستگاه‌های اضافه‌شده کار نخواهند کرد. فایل‌ها را پاک نکنید و بدون تأیید کاربر بکاپ را روی فایل فعلی overwrite نکنید.

## پروفایل‌های اتصال: بررسی 2026-09-08

منابع رسمی خوانده‌شده:
- https://xtls.github.io/en/config/transports/websocket.html
- https://github.com/XTLS/Xray-core/discussions/4113

مستند WS مهاجرت به XHTTP را به خاطر ویژگی‌های قابل‌شناسایی پیشنهاد می‌کند. راهنمای XHTTP دربارهٔ modeهای مختلف و رفتار reverse proxy توضیح می‌دهد. این توصیه به معنی تضمین سازگاری Hostim یا اپراتور خاص نیست. در این انتشار، مسیر سالم WS دست‌نخورده باقی می‌ماند و XHTTP «فعال‌نشده» برچسب دارد. Fragment/Mux/DNS سمت کلاینت‌اند و این پنل آن‌ها را مخفیانه اعمال نمی‌کند. پروفایل تحقیق XHTTP فقط برای ثبت نتیجهٔ آزمایش مستقل است.

دفتر آزمایش شامل شبکه، کلاینت/نسخه، پروفایل، نتیجه و تاخیر اختیاری است. نتایج **گزارش دستی مدیر** هستند، نه تست خودکار ایجنت و نه تضمین عملکرد آتی.

## اعتبارسنجی این انتشار

- ۲۴ تست Python موفق: HTTP API، امنیت، حفظ UUID/بکاپ، عدم افشای داده، فیلتر/retention، بازیابی نشست قطع‌شده، جلوگیری از spoofing XFF، parser فریم fragmented و آزمون relay با سوکت واقعی و WS peer کنترل‌شده.
- تست relay از peer آزمایشی استفاده می‌کند، **نه Xray واقعی**؛ برابر بودن بایت‌های ورودی/خروجی و ذخیرهٔ شمارنده را بررسی می‌کند.
- تست jsdom علیه HTTP API واقعی: ورود، افزودن دستگاه، دریافت لینک، سه پروفایل و تاریخچهٔ خالیِ بدون جعل؛ این تست رندر بصری مرورگر نیست.
- Docker در این محیط موجود نیست. دانلود Xray و Chromium با خطای TLS شبکه مواجه شد. بیلد کامل ایمیج، سازگاری بستهٔ maxminddb در build و تونل انتهابه‌انتها باید روی اپ preview میزبان تأیید شوند. نسخهٔ Xray پین‌شده همان نسخهٔ قبلی است.
