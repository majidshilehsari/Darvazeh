# دروازه — پنل خصوصی اتصال روی Hostim

نسخهٔ فعلی **0.2.0-preview.1**، مستقل و **نه مرزبان**: پنل فارسی تک‌مدیر، مدیریت دستگاه با لینک مستقل، VLESS/WebSocket، تاریخچهٔ خصوصی، گزارش و راهنمای آزمایش. راهنمای کامل نسخهٔ جدید در `docs/ADVANCED-PANEL.fa.md` است.

## معماری

```text
Client -- HTTPS:443 --> Hostim (TLS termination)
                            |
                       Nginx :8080
                       /          /connect
                 Python :8081    observer :10001 → Xray :10000
```

پورت‌های داخلی فقط روی loopback هستند. مسیر `/connect` ثابت است. گواهی و TLS عمومی را Hostim مدیریت می‌کند. این طرح به پشتیبانی WebSocket در ورودی Hostim نیاز دارد. Reality و ورودی UDP ارائه نمی‌کند. اتصال روی همراه اول تضمین نمی‌شود.

## نصب روی Hostim

1. پروژه را از همین مخزن و **شاخهٔ `arena/01a080a2-darvazeh`** با Dockerfile ریشه متصل کنید. تا وقتی شاخه در GitHub پوش نشده، Hostim به تغییرات محلی دسترسی ندارد.
2. یک اپ جدا برای آزمایش بسازید؛ سرویس سالم قبلی را تغییر ندهید. هزینهٔ اپ و فضای ذخیره‌سازی را بررسی کنید و از مجازبودن کاربرد در شرایط میزبان مطمئن شوید.
3. HTTP Service را فعال و پورت داخلی را **8080** تنظیم کنید. healthcheck پنل: `/healthz` (سلامت پنل است، نه تست اتصال VPN).
4. یک **Volume دائمی در `/data`** وصل کنید. فایل‌های `settings.json` و `xray.json` حاوی UUID محرمانه هستند. بدون Volume شناسه ممکن است در دیپلوی بعدی عوض شود.
5. متغیرها:
   - `ADMIN_PASSWORD`: رمز تصادفی حداقل ۱۶ کاراکتر؛ پیشنهاد: خروجی `openssl rand -hex 24`. در گفتگو یا Git نگذارید.
   - `PUBLIC_DOMAIN`: دامنه‌ای که Hostim به **این اپ جدید** می‌دهد؛ فقط hostname، بدون `https://` یا مسیر.
   - **`DEMO_MODE` را در محیط واقعی تنظیم نکنید.**
6. دیپلوی کنید و پس از آماده‌شدن گواهی، دامنه را با **HTTPS** باز کنید. با رمز مدیر وارد شوید. «هسته در حال اجرا» باید دیده شود؛ سپس لینک اتصال را بگیرید.
7. روی ایرانسل و همراه اول با همان دستگاه و کلاینت تست کنید. نتیجهٔ تست اپراتور را کنار گزارش پنل ارسال کنید؛ گزارش به‌تنهایی مسیر شبکهٔ کاربر را نشان نمی‌دهد.

این راهنما نام/شمارهٔ دکمه‌های نسخهٔ فعلی داشبورد Hostim را حدس نمی‌زند؛ پورت، مسیر Volume و متغیرها الزامات فنی هستند.

## کنترل و حریم خصوصی

- رمز در محیط سرور؛ مقایسهٔ scrypt، کوکی HttpOnly/Secure/SameSite و نشست ۸ ساعته؛ تغییرات نیازمند CSRF هستند.
- محدودکنندهٔ ورود: ۱۰ تلاش در دقیقه به‌صورت سراسری. برای سرویس بزرگ مناسب نیست؛ مهاجم می‌تواند موقتاً ورود مدیر را محدود کند.
- خطاهای اعتبارسنجی کانفیگ قبل از توقف هسته بررسی می‌شوند. اگر فرایند جدید فوراً متوقف شود، تنظیم قبلی بازیابی می‌شود. امکان قطع ارتباط هنگام اعمال وجود دارد.
- هستهٔ متوقف‌شده خودکار وارد حلقهٔ ری‌استارت نمی‌شود؛ رویداد توقف ثبت و دکمهٔ ری‌استارت در پنل فراهم است.
- ۱۵۰ رویداد آخر ورود، تغییر و وضعیت فرایند در RAM هستند؛ پایدار نیستند. خروجی خام هسته دور ریخته می‌شود تا مقصد کاربران وارد لاگ نشود. بنابراین سطح لاگ Xray در این نسخه گزارش فنی خام قابل دانلود تولید نمی‌کند.
- گزارش فاقد رمز/UUID/لینک/CSRF است، اما **دامنه** را دارد. مصرف نمایش‌داده‌شده بیشینهٔ حافظهٔ فرایند پنل است، نه کل سرور.
- محدودکردن IPهای خصوصی در روتینگ Xray دفاع پایه است؛ جایگزین ایزوله‌سازی شبکه توسط میزبان نیست.
- پنل سهمیه/انقضا، شمارش قطعی انسان‌های آنلاین، تست سرعت خودکار، اعمال Fragment سمت کلاینت یا دسترسی دائمی دستیار ندارد. مدیریت دستگاه‌ها و شمارش اتصال‌های WS در نسخهٔ 0.2 اضافه شده‌اند.
- برای عیب‌یابی گزارش را دانلود کنید و همراه نسخهٔ کلاینت، اپراتور و متن خطای حذف‌شده از اطلاعات حساس بفرستید. لینک خصوصی را منتشر نکنید.

## آزمایش محلی

```sh
python3 -m unittest discover -s tests -v
DEMO_MODE=1 ADMIN_PASSWORD=demo-password-2026 PUBLIC_DOMAIN=demo.example DATA_DIR=/tmp/darvazeh-demo PORT=8081 python3 app/server.py
```

این اجرا فقط پنل است؛ هسته را اجرا نمی‌کند و با برچسب نمایشی مشخص می‌شود. ورود در حالت نمایشی هم لازم است.

برای اجرا با Docker، متغیرها را در `.env` (نادیده‌گرفته‌شده در Git) قرار دهید و `docker compose up --build` اجرا کنید. این پیکربندی تولید برای HTTPS پشت میزبان طراحی شده و کوکی ورود روی HTTP محلی کار نمی‌کند؛ یک reverse proxy HTTPS لازم است.

## وضعیت اعتبارسنجی نسخهٔ اولیه (برای نتایج نسخهٔ جدید، بخش آخر را ببینید)

۷ تست یکپارچه با اجرای واقعی HTTP پنل در حالت نمایشی: الزام ورود، رمز اشتباه، Origin، CSRF، تغییر شناسه و حذف اطلاعات حساس گزارش، اعتبارسنجی تنظیمات، خروج. syntax پایتون و Bash نیز بررسی شد.

Docker در محیط ساخت این پروژه موجود نبود؛ دریافت باینری Xray از میزبان فایل‌های GitHub با خطای TLS محیط مواجه شد. بنابراین **بیلد کامل کانتینر، آزمون خود Xray و اتصال انتهابه‌انتها هنوز تایید نشده‌اند**. نسخه و SHA-256 دو معماری از API ریلیز رسمی v26.3.27 گرفته شده و هنگام Docker build بررسی می‌شوند. قبل از جایگزینی سرویس اصلی، حتماً اپ آزمایشی را تست کنید.

## اصلاح راه‌اندازی در 0.1.0-preview.2

- نقص متغیرهای محیطی دیگر باعث خروج کل برنامه نمی‌شود: صفحهٔ اصلی و `/healthz` فعال می‌مانند و `/api/bootstrap` فقط کدهای خطای غیرمحرمانهٔ راه‌اندازی و شمارهٔ نسخه را می‌دهد.
- قبل از ورود، علت دریافت‌نشدن/کوتاهی رمز یا دریافت‌نشدن/قالب نامعتبر دامنه به فارسی نمایش داده می‌شود؛ مقدار رمز و دامنه در این endpoint منتشر نمی‌شود.
- رمز غایب/کوتاه یا خطای آماده‌سازی رمزنگاری: ورود غیرفعال است؛ دسترسی عمومی به مدیریت، گزارش یا لینک اضافه نشده است.
- با رمز معتبر می‌توان وارد شد و خطای دامنه، داده یا هسته را دید. تا پایان راه‌اندازی و رفع خطاها لینک آماده ارائه نمی‌شود. خطای هسته در گزارش به‌صورت کد دسته‌بندی‌شده است، نه خروجی خام دارای اطلاعات حساس.
- هسته در پس‌زمینه آماده می‌شود؛ healthcheck منتظر تست Xray نمی‌ماند. سلامت پنل معادل سلامت VPN نیست.
- فایل settings موجودِ نامعتبر حفظ می‌شود؛ هیچ بازیابی با ساخت UUID جدید به‌صورت خودکار انجام نمی‌شود. خطای Volume هم صفحه را از دسترس خارج نمی‌کند.
- اصلاح Envs باید در Hostim انجام و با Restart اعمال شود؛ هیچ فرم عمومی تغییر رمز یا خواندن خودکار `.env` در کانتینر اضافه نشده است.
- ۱۳ تست موفق: ۷ تست قبلی به‌علاوهٔ تست‌های HTTP حالت واقعی با رمز غایب/کوتاه، دامنهٔ غایب/نامعتبر، Xray غایب و دادهٔ خراب/غیرقابل‌دسترسی. Docker و اتصال واقعی Hostim هنوز در این محیط تست نشده‌اند.

## نسخهٔ پیشرفته: 0.2.0-preview.1

[راهنمای دقیق قابلیت‌ها، حریم خصوصی، IP و کشور و بازگشت امن](docs/ADVANCED-PANEL.fa.md)

مدیریت دستگاه با لینک مستقل، تاریخچهٔ ۷روزه در SQLite، زمان شروع/پایان مشاهده‌شده، بایت‌های عبوری با سربار، فیلتر اتصال‌ها و دفتر آزمایش پروفایل‌ها اضافه شد. لینک قبلی حفظ می‌شود. مسیر HTTP عمومی همچنان 8080 و مسیر اتصال `/connect` است.

معماری جدید WS: `Nginx → observer:10001 → Xray:10000`؛ با `MONITOR_ENABLED=0` و Restart می‌توان بدون حذف داده به مسیر مستقیم قبلی برگشت. فقط یک replica استفاده شود.

IP واقعی فقط پس از تأیید زنجیرهٔ پراکسی Hostim و تنظیم `TRUSTED_PROXY_CIDRS` قابل‌انتساب است؛ بانک MMDB کشور باید جداگانه و طبق مجوز در `/data/GeoLite2-Country.mmdb` قرار گیرد. بدون این دو پیش‌نیاز «نامشخص» نشان داده می‌شود، نه IP/کشور جعلی. XHTTP در این نسخه نصب نشده است؛ در پنل با برچسب پژوهشی و راهنمای مستند آمده است.

۲۴ تست Python و یک سناریوی jsdom با API واقعی موفق شدند. اتصال Xray واقعیِ این نسخهٔ پیشرفته هنوز در این محیط آزموده نشده است؛ روی اپ preview تست کنید.
